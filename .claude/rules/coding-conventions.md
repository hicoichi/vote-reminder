# コーディング規約

本プロジェクトは試しに作るPoCであり、作り込みは行わない前提で以下の規約を適用する。

## 基本方針

* シンプルさを最優先する。過剰な抽象化・共通化・将来を見越した設計はしない。
* 「動くものを最小限で」を優先する。3行程度の重複は許容し、無理に共通化しない。
* 依頼された範囲を超えて機能を追加・リファクタリングしない。
* バウンダリ（ユーザー入力・外部API呼び出し）以外での過剰なエラーハンドリング・バリデーションはしない。
* フィーチャーフラグや後方互換シムは作らない。不要になったコードは残さず削除する。

## コメント・ドキュメント

* コード内コメントは日本語で、必要最小限（自明でない理由・制約がある場合のみ）。
* 関数・変数が何をするかはコメントではなく命名で表現する。
* README等のドキュメントは日本語で作成する。

## 命名・構成

* 変数・関数名は具体的で意味の分かる名前にする（省略しすぎない）。
* ファイル・ディレクトリ構成は使用する技術スタックの標準的な慣習に従う。

## テスト

* 主要な正常系のみ最小限カバーすれば良い。網羅的なテスト・カバレッジ目標は設定しない。
* テストのためだけの過剰なモック化・抽象化はしない。

## Git

* コミットは意味のある単位で分割する。
* コミットメッセージは「何を」より「なぜ」を簡潔に書く。
